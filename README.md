# Java Applications

Small Java Swing and AWT programs written more than ten years ago, recovered and now playable in a browser. [HISTORY.md](HISTORY.md) tells how they got here.

Sources recovered from the jars published at https://nathangawith.com/applications/java, decompiled with Vineflower 1.10.1.

CircleSpawner, DinoGame, StockChecker, SynthesizerKeyboard, Windows and WindowsE are no longer on the site. They were recovered from the git history of https://github.com/Nate314/site (`assets/javaApplications/`).

BibleDownloader, GroupCreator, MusicTheoryExpert, NumberGuess, SimpleAlgorithms and TankGame came from the author's own files. MusicTheoryExpert, NumberGuess, SimpleAlgorithms and TankGame are the original Eclipse source (only `src/` is kept). BibleDownloader (`BibleDownloader1.3.1.jar`) and GroupCreator were decompiled. `AudioBibleDownloader1.1.jar` was left out: BibleDownloader 1.3.1 is a later version of the same app that keeps its MP3 download and adds chapter text.

Each project has its sources in `src/` (decompiled ones with their original `META-INF/MANIFEST.MF`) and its own README.

## Notes

- Most jars were obfuscated (single-letter names like `a`, `b`). Those identifiers have been renamed by hand to descriptive English names. NathaNOS and ScreenSaver were not obfuscated.
- The apps have since been modernized: the bugs listed in the per-app READMEs were fixed, the UIs start with `SwingUtilities.invokeLater`, animation and timed work runs on `javax.swing.Timer` instead of sleeping or busy-waiting on the event thread, and a few small features were added (each app README lists its controls). Apps with fixed game logic have an assert-based self-check under `<App>/test/`.
- The obfuscator stripped inner-class metadata, so a few files were fixed by hand to compile:
  - `Clock/src/clock/ClockTicker.java`: added the outer `Main` field and replaced synthetic accessors with direct field reads.
  - `FlappyBird/src/flappyBird/RenderLoop.java`: added the outer `GamePanel` field and inlined the synthetic accessors (verified against the original bytecode). `RenderLoop` was later removed when the game moved to a Swing timer.
  - `NathaNOS/src/main/StartMenu.java`: repaired the anonymous `JPanel` subclass.
  - `DinoGame/src/dinosaurgameplayer/ObstacleDetector.java`: added the outer fields and replaced the synthetic accessor with a direct call to the sleep helper (verified against the original bytecode). The sleep helper was later replaced by a one-shot Swing timer.
  - `SynthesizerKeyboard/src/synthesizer/TickCounter.java`: added the outer `KeyboardWindow` field. `KeyboardWindow.java`: added `(Integer)` casts the decompiler dropped. Both were later replaced when click-to-play was fixed.
  - `Windows/src/test/Test.java`: added `throws Exception` to `main`, since javac requires the checked exceptions the bytecode leaves undeclared.
- In BibleDownloader (`DownloadManager.java`) and GroupCreator (`Main.java`), the decompiler could not rebuild three try-with-resources blocks, so they were rewritten as `try (Writer writer = ...)`.
- Windows sends a real Windows key press with `java.awt.Robot` as soon as it starts, and so does DinoGame's original screen bot (`./run.ps1 DinoGame screen`: Space, to play the Chrome dino game); plain `./run.ps1 DinoGame` opens its own game window instead. WindowsE presses Win+E repeatedly when its button is clicked, opening File Explorer windows.
- StockChecker no longer downloads quotes (the Yahoo Finance CSV API is retired). Its desk opens day 1 at the prices in the committed `stockCheck.csv`, saves ticker list edits back to `myStocks.txt`, and keeps the practice desk in `~/.stockchecker-desk.txt`.
- FlappyBird and NathaNOS load images by relative path, so run them from the folder holding the images:
  - FlappyBird: run from `FlappyBird/src` with a numeric argument, e.g. `java flappyBird.Main 120` (the original `run.bat` used 120).
  - NathaNOS: run from a folder holding its `assets/`. `assets/Clock.jar` is an older Clock build that shipped in the zip, kept as a binary asset. `./run.ps1 NathaNOS` stages a copy in `out/NathaNOS/desktop/` with every other app except Windows and WindowsE on its desktop.

## Build and run

Requires a JDK (`java` and `javac` on PATH). From the repo root in PowerShell:

```powershell
./run.ps1                      # opens the launcher, then compiles and runs the app you pick
./run.ps1 Minesweeper          # compiles and runs Minesweeper
./run.ps1 Minesweeper -Build   # builds out/Minesweeper.jar instead of running
```

With no app name, `run.ps1` opens the [Launcher](Launcher/README.md): all 20 apps as cards with their pictures, filters for games, music, toys, tools and the apps that press real keys, a search field that has the keyboard from the start, and Enter to play. It remembers what you launched (in `~/.oldjava-launcher.txt`), opens on the last one, marks the rest New, and Pick for me plays one you have not tried. Apps that press real keys (Windows, WindowsE) say so with a Real keys chip and ask first. It reads the apps' names, hints and thumbnails from the web gallery, so both front doors describe them the same way.

Run mode launches each app from the folder it expects (for example `FlappyBird/src` with argument `120`), with any non-Java files in `src/` on the classpath. Build mode prints the matching `java -jar` command. Build output goes to `out/`, which is git-ignored.

## Web (TeaVM)

Every app also runs in a browser, compiled to JavaScript with TeaVM on a small AWT/Swing compatibility layer. Requires Maven 3.9. From the repo root:

```powershell
mvn -f web/pom.xml package                               # builds the static site into web/target/site
python -m http.server 8000 --directory web/target/site   # then open http://localhost:8000/
```

Next to Modern, Classic and Arcade, the skin picker has Yours: a skin the visitor makes in a panel beside the running app (light or dark, any color, one of six desk wallpapers, corners and window chrome), worn by every page and app as it is chosen, and sent to a friend as a `?skin=` link (see [Your skin](web/README.md#your-skin)).

Ctrl+K (Cmd+K on a Mac) on any page of the site opens Find: one box that finds any app (and its Then version, or the computer playing it), anything the page can do (skins, sound, share, replay, the source, records, an app not played yet) and any Java source file of any app, opened in its Source panel (see [Find](web/README.md#find)).

Two apps can run at once, the way they did on a desktop: Side by side in an app page's toolbar opens a second app in a panel beside the first (Clock's focus timer beside a game, the chord finder beside the keyboard), each with its own half of the screen. It stays open from app to app, Swap trades the two, and its edge drags to resize (see [Side by side](web/README.md#side-by-side)).

Apps open without a wait: pointing at a link to an app (Switch app, Next, a gallery card, an exit suggestion, Find's highlighted result) gets that page ready in the background, so in Chrome and Edge the click shows its title screen already loaded with Play lit, and the home page's player fetches the app it is pointed at ahead of the click (see [Instant open](web/README.md#instant-open)).

The apps also play as they were first restored, before the reworks: 17 of them have a Then | Now switch (on their page and in the home page's player) that runs the code as it was on master after #9 (the recovered code with the light bug fixes of #6), compiled from the repo's git history at a pinned commit, with the known quirks its README still listed then (see [Then and now](web/README.md#then-and-now)). The build reads that history with `git`.

The site can be hosted on GitHub Pages at https://nate314.github.io/old-java-applications/: `.github/workflows/pages.yml` builds and deploys it on every push to `master`, once Settings > Pages > Source is set to GitHub Actions (see [GitHub Pages](web/README.md#github-pages)).

On a phone the home page's player gives the app the phone's screen: it used to shrink a desktop-sized screen to a third of its size (Minesweeper's tiles 7 px wide), and now the app fits its windows to the phone's width and the height under a compact bar (see [Home page](web/README.md#home-page)). On a phone or tablet every app plays by touch: a tap clicks, a finger drags windows, dials and anything else the apps drag with the mouse, a quick double tap double-clicks, and a long press on Minesweeper's tiles is the right click that flags them (see [Touch](web/README.md#touch)).

A game controller plays them too: press any button on it and the page shows what each button does in that app. Its buttons press the app's own keys (the D-pad flaps, jumps, drives a tank or plays the Synthesizer's white keys, and a second controller drives TankGame's green tank), a pointer drawn on the page does the clicking everywhere else (A clicks, B right-clicks, so Minesweeper flags too), and the bumpers flip to the previous or next app (see [Game controllers](web/README.md#game-controllers)).

In browsers with Document Picture-in-Picture (Chrome, for one) an app can also pop out of the page: Pop out moves it, still running, into a small window of its own that stays on top of every other window on the screen, so a timer, a song or a game can sit beside whatever else is open (see [Pop out](web/README.md#pop-out)).

Records travel too: the home page's Your records lists what every app saved in the browser (with the same record lines as the title screens) and carries it elsewhere. Send to my phone shows a QR code of a link that holds the saves, Download and Load move them as one `oldjava-saves.json` file, and the desktop launcher's Saves button reads and writes that same file, so a best time set in the browser can be loaded into the desktop app and back. Nothing changes until the visitor ticks which apps take the incoming records (see [Your records](web/README.md#your-records)).

The Screen Saver app is the site's screen saver too: a page left alone for 3 minutes fades in the saver the visitor picked in the app, and the first key, click or real mouse move brings the page back without that input reaching the app beneath, then says what it was, with a way to pick another saver or turn it off (see [The site's screen saver](web/README.md#the-sites-screen-saver)).

The site keeps its own changelog, read from this repo's git history when it is built: the home page's What's new shows the latest changes with a Play button for each app they changed, and names the apps a returning visitor has played that changed since they last played them (their gallery cards say Updated), and every app page's title screen lists that app's story, every change to it since its recovered code was first committed (see [What's new](web/README.md#whats-new)).

Four games can play themselves, so a visitor sees them in motion before deciding to play: Minesweeper's computer solves the board (flagging what is certain, guessing only when it must), Ultimate Tic-Tac-Toe's computer plays both sides, TankGame's computer drives both tanks, and DinoGame's original bot runs. The home page opens on Minesweeper playing itself and, until the visitor picks an app, moves on to the next of the four every 40 seconds; the first click or key in the player takes over the game where it stands, and only then does the passport stamp it. The same keys work on the desktop (W in Minesweeper and Ultimate Tic-Tac-Toe, C in TankGame, B in DinoGame), and the four title screens offer "Watch the computer play it first" (`?watch`). Games the computer played in do not count toward best times or records (see [Watch the computer play](web/README.md#watch-the-computer-play)).

Every running app also keeps its last 10 to 20 seconds as video, so a close call, a high score or a tune can be kept after it happened: Replay (in the toolbar, on the exit screen and in the home page's player bar) shows the clip, with the app's own sound, to save as an MP4 (WebM in Firefox) or send to the system share sheet. Nothing is recorded to disk or sent anywhere unless the visitor saves or shares it. Keeping those seconds costs next to nothing while the app is still: only an app that changed is drawn into the video again (once a second otherwise), and nothing is recorded while the app is scrolled out of view or its tab is hidden, so an idle app page, which used to keep more than half a CPU core busy recording, now uses under a tenth (see [Instant replay](web/README.md#instant-replay)).

Some moments are a picture rather than a video (a Circle Spawner heart, a painting on NathaNOS, a solved cube), so every app can also be photographed: Photo (the camera in an app page's toolbar and in the home page's player bar, where it is the camera alone) flashes the stage, clicks a shutter and shows the app's windows as a print at up to twice their size, in one of three frames: Instant (a white instant-camera print with a handwritten caption you can edit), Postcard ("Greetings from" the app over the picture, a stamp of its thumbnail and a postmark of the day) or Plain (the windows with a camera's orange date stamp). Save picture downloads it as a PNG, and Copy picture and Share... appear where the browser supports them. See [web/README.md](web/README.md#photo-booth).

The keyboard reaches every app too: Tab and Shift+Tab move through an app's buttons and fields in Swing's order and then on out to the page (before, every key went to the app, so the page's toolbar could not be reached without a mouse), windows are named by their titles for screen readers, and apps name their buttons with Swing's own accessible names. Minesweeper is now played entirely from the keyboard (arrow keys move a cursor over the tiles, Space reveals, F flags, on the desktop too) and says what each tile is; Ultimate Tic-Tac-Toe names every square and the computer's last move (see [Keyboard and screen readers](web/README.md#keyboard-and-screen-readers)).

The site can be installed as an app, and Save all for offline on the home page keeps all 20 apps (about 12.7 MB; Bible Downloader still needs a connection for the chapters it has not fetched) in the browser so they play with no connection.
