# Launcher

The front door for the desktop: `./run.ps1 old` with no app name asks for it or the web site, and Enter opens it. Every app in this repo is a card with its picture, category and how often you have played it, and Enter plays the selected one. It replaces the numbered list `run.ps1` used to print and ask about. Unlike the other folders, this is not a recovered app: it was written for this repo.

## Controls / usage

- **Cards**: one per app, all 20 in the web gallery's order. Each shows the app's thumbnail, its category and the start of its hint, so the cards say what each app is before you pick one. An app not launched here yet has a NEW badge and two lines of its hint; one you have played has one line of hint over "Played 3 times, last yesterday" (or its newest change, or how long you have played it). An app that is running says so with a green RUNNING badge. Pointing at a card shows its whole hint.
- **Colors from each picture**: every picture sits on a blurred, dimmed copy of itself that fills its box, so a wide picture like Dino Game's or a tall one like Rubik's Cube 2D's is framed in its own colors instead of dark bars, and the cards read as 20 different apps at a glance. Selecting a card washes the top of the detail pane in that app's color (its picture's pixels averaged, the colorful ones counting most, kept dark so the words stay readable), and the wash stays when a short window has no room for the picture. Then mode's lines-of-Java card keeps its plain dark box.
- **Search**: the field at the top right has the keyboard from the start. Typing narrows the cards to apps whose name, folder name, category or hint contain the text. **Esc** clears it.
- **Arrow keys** move the selection (Up and Down by a row; Left, Right, Home and End while the search field is empty). **Enter** plays the selected app, from anywhere in the window.
- **Filters**: All, Games, Music, Toys, Tools and Real keys (the apps that press real keys), each with its count, and Updated while some app has changed since you last played it. The chips wrap onto a second row when the window is too narrow for them.
- **What is new since you last played**: the apps keep changing (new modes, keys and fixes land in their folders), so the launcher remembers, for each app you launch, the newest commit that had changed its folder by then. An app with newer commits since gets a purple badge saying how many ("3 UPDATES") and its newest change on its card ("New: Zoom (Z) for tiles big enough to tap"), and in the detail pane its hint gives way to "3 things new since you last played:" with the two newest commit subjects and the day each landed ("today", "4 days ago"; the rest are in History). Housekeeping does not count as new: commits whose subjects the web site's What's new folds into Behind the scenes (README and check updates, refactors, retaken pictures, round fit-ups) are left out of the badge, the card, the Updated filter and Pick for me, by the same rule (`History.QUIET`, copied from `web/src/runtime/lazy/news-kind.ts`). They still show in History. The status line says how many of your apps changed when the launcher opens, and the Updated filter lists them. Playing the app clears it. Apps never launched keep their NEW badge instead. It needs the git history Then uses; for launches from before the launcher kept the commit, the commits dated after the last launch count as new.
- **Order** (Alt+O, beside Saves): cycles the cards between Gallery (the web gallery's order), Recently played (the app you launched last first) and Most played (the apps you have spent the most time in first, each card saying how long, like "1 h 30 min played"). Apps not played yet follow in the gallery's order. The choice is kept for next time. The cards move only when you change the order or an app closes, never under the pointer while you pick.
- **Time played**: the launcher times each app from Play until its window closes (run.ps1's compile included), so the detail pane says "2 h 5 min played in all, longest 40 min" under the play record, and the status line says how long that play was when an app closes. Then plays are not timed.
- **Click** a card to select it, **double-click** to play it.
- **Detail pane** (right): a larger picture, the name, Decompiled jar or Original source, the hint, the play record, **Play** (Alt+P), **Read me** (Alt+R: the app's README in a window, Esc closes it) and **Open folder** (Alt+F). On a window too short for all of it, the picture shrinks first and then the pane scrolls, so Play stays in reach.
- **Saves** (Alt+S): moves the apps' records between this computer and the web site. **Save a file...** writes every save file the apps keep in your home folder (`.minesweeper-best.txt`, `.clock.txt` and the rest), plus which apps you have launched, to `oldjava-saves.json` (in Downloads by default), for Your records > Load on the site. **Load a file...** reads a file from the site's Download (or from another computer), lists its apps with a box each (ticked where its records differ from the ones here) and writes the ticked apps' files over yours. Dropping a saves file onto the launcher window (on the cards, the detail pane or the header, not the search field) does the same as Load a file... without the file chooser. Only the save files listed in `SaveBundle.java` are ever written, by name, into the home folder; the site's Then saves and its other files are left out. An app already running keeps its old records until it is started again.
- **Then and now** (Alt+T and Alt+N, above Play): Then plays each app as it was first restored, the same version the web site's Then pages run (commit `5a28e46`: the recovered apps with the light bug fixes of #6, before the reworks). In Then mode the picture well shows the app's lines of Java then and now as two bars, the hint is the first lines of its README as it was then, each card's bottom line reads like "450 lines then, 1,915 now", Play turns brown ("Play it as first restored") and Read me opens the README as it was then. An app whose code has not changed since would say so and run today's; Windows was the last such app until it became an on-screen Windows key in round 12 (#97), so Then now plays the first restored copy of every app. Today's and the first restored version of one app can run at the same time, side by side; the card says RUNNING THEN while the old one runs. The first restored Dino Game is the original screen bot, which presses real Space keys, so it carries a warning (taken from its old README) and asks first, like the Real keys apps. Then launches do not count in the play record, and Pick for me always plays today's version.
- **History** (Alt+H): every commit that changed the app's folder since it was first restored, newest first with dates, plus its lines of Java then and now.
- **Start menu** (Windows only; Alt+M, under Read me): **Add to Start menu** puts the selected app in the Windows Start menu, in an Old Java Applications folder, and **Add all 18** puts in every app but the two that press real keys (a shortcut would start them without the launcher's warning). Then the Windows key and a few letters of an app's name ("mine", Enter) play it without opening the launcher. Each shortcut runs `run.ps1 old <App>` from the repo in a minimized console, with the app's picture (cropped to a square and ringed in its category's color) as its icon. The buttons turn into **Remove from Start menu** and **Remove all**, which delete the shortcuts, their icons and the folder. Start menu launches do not count in the play record, and moving the repo breaks the shortcuts until they are added again.
- **Pick for me** (Alt+K): plays a random app you have not launched yet, from the cards shown (or from all, if none of those qualify); once you have launched them all, one that has changed since you last played it. It never picks an app that presses real keys.
- **Apps that press real keys** (Windows, WindowsE) carry a Real keys chip, show a "Heads up" note and an orange Play button, and ask before they start.
- **Watching an app start**: run.ps1 compiles an app before its window opens, which takes a few seconds, so Play shows where the launch has got to instead of going gray. While it starts, Play stays in the app's color with a band of light crossing it and three bars along its bottom that light up as it gets ready, builds ("Building it from source...", while javac runs) and opens ("Opening its window...", for the first 2 seconds of the app's own java); the card's picture has the same band of light and a BUILDING or OPENING badge, and the status line says each step. Once running, Play turns green and counts up ("Running for 3:12"), as does the card's badge ("RUNNING 3:12"). The steps are read from the programs run.ps1 has started (`Runner.phase`), in the background a few times a second, and never step back.
- The launcher opens on the app you launched last, and stays open while apps run, so several can run at once. The same app cannot be started twice at once. The status line at the bottom says when an app starts, closes, or stops with an error (the details are in the console that ran `run.ps1`).
- The window is resizable (at least 780 x 620); the cards reflow into as many columns as fit.

## Where things come from

- **Names, hints, categories, origins and thumbnails** of all 20 apps are read from `web/src/shared/apps.json` (the list the site's home page renders) and the screenshots in `web/public/shots/`, so that file stays the one place that describes an app. It describes what Windows and Windows+E do on the site's pretend Windows, so their hints here, and their warnings, come from `Catalog.java`, written from their READMEs. An app without a screenshot would get a drawn card with its initials.
- **Playing an app** runs `run.ps1 old <App>` in the PowerShell that started the launcher, from the repo root, so each app is compiled and started from its own working folder exactly as from the command line. Its output goes to the same console.
- **Then** comes from the repo's git history, so it needs git on the PATH and a clone with history back to `5a28e46` (without them the Now and Then buttons and History are hidden). The stories (lines of Java counted with `git grep`, the commits with `git log --no-merges`, the old READMEs with `git show`) are read in the background when the launcher opens. The first Then play unpacks that commit (everything but `web/`) with `git archive` into `out/then`, which is git-ignored, and runs that commit's own `run.ps1 <App>` there, so the old app is compiled and started exactly as it was then. Today's original art is copied over the old pictures (`ThenCopy.ART`; the ones nothing reads any more are left out), so FlappyBird, BibleDownloader and NathaNOS look as they do today: the old pictures were taken from other apps. Its home folder is `~/.oldjava-then` (set through `JAVA_TOOL_OPTIONS`, which is why the console prints "Picked up JAVA_TOOL_OPTIONS"), so the only first restored app that saves, Flappy Bird's high score, keeps its own file apart from today's. Delete `out/then` to unpack again.
- **The play record** (how many launches, and the last) is saved to `.oldjava-launcher.txt` in the user's home folder, one `App count lastLaunchMillis` line per app. It counts launches from the launcher only. Delete the file to start over. Beside it, `.oldjava-launcher-seen.txt` keeps one `App commit` line per app: the newest commit that had changed the app's folder when it was last launched, which is what "New since you last played" counts from. It is a file of its own so that an older launcher still reads the play record. For the same reason the time played is in `.oldjava-launcher-time.txt` (one `App totalMillis longestMillis` line per app) and the Order choice in `.oldjava-launcher-order.txt`. Neither travels in the saves file.

## Code layout

- `src/launcher/Main.java`: entry point; reads the catalog from the current folder (the repo root) and opens the window. The optional argument is the PowerShell to run `run.ps1` with (default `powershell`).
- `src/launcher/Catalog.java`: the list of apps; parses the gallery and gives the two that press real keys their desktop hint and warning.
- `src/launcher/LauncherWindow.java`: the window: header with search and filters, the card grid, the detail pane, keys and launching.
- `src/launcher/SaveBundle.java`: the saves file shared with the web site: the save files each app keeps, reading them from and writing them to the home folder, and the JSON (with a small reader of its own).
- `src/launcher/SavesMenu.java`: the Saves button's dialogs and file choosers.
- `src/launcher/StartMenu.java`: the Start menu shortcuts: their names, the command they run, the icons (written to `out/start-icons` as one 256 px PNG in an .ico) and the PowerShell (WScript.Shell) that makes them.
- `src/launcher/PlayLog.java`: the play record file, its "Played twice, last yesterday" wording, and the commit each app had when last launched.
- `src/launcher/Runner.java`: starts an app in its own process (`run.ps1`), reads how far its launch has got from the programs under it, and reports its exit code; the Then runner unpacks the first restored code first and gives it its own home folder.
- `src/launcher/History.java`: each app's then and now from git: lines of Java, the commits since, its README as first restored, and the warning for a first restored app that presses keys.
- `src/launcher/ThenCopy.java`: unpacks the first restored commit into `out/then` once (refusing any path outside it), with today's art over the old pictures.
- `src/launcher/Git.java`: runs git in the repo.
- `src/launcher/Thumbs.java`: loads and scales the thumbnails, draws the cards for apps without one, and makes each picture's glow (blurred once per app, then fitted and rounded per box size) and its tone.
- `src/launcher/ReadmeView.java`: shows a README, turning a small part of Markdown into Swing HTML.
- `src/launcher/Ui.java`: colors, fonts, the flat buttons, the search field and the thin scroll bar.

## Running

From the repo root: `./run.ps1 old` (or `./run.ps1 old Launcher`). It must run from the repo root, which `run.ps1` does.

## Self-check

`test/launcher/LauncherCheck.java` checks that the catalog has all 20 apps (each with a README, a `run.ps1` entry and a thumbnail), the two that press real keys, search, the play record file and its wording, the card's two-line pitch (wrapped at words, cut with "..."), the picture glow (the box's size, rounded corners, dimmed but still the picture's color) and tone (a red picture gives a dark red, a gray one stays gray), the README conversion, and the saves file: each listed save file is named in its app's sources and every home-folder `.txt` an app's sources name is listed (so a new save file cannot be left behind), a save and load keeps every byte, a file as the web site writes it loads, and files not listed (or hostile paths) are never written. It also checks Then: the commit matches `web/then/pom.xml`, every app has a first restored story, Minesweeper grew, only the first restored Dino Game warns, Windows grew (its on-screen key), that an unpacked first restored copy has today's art and not the removed pictures, and the unpacker refuses an archive path outside its folder (the git checks are skipped without history). What is new: the commit seen at a launch is kept beside the play record (whose format stays the same), and the changes since are the ones above it, or the ones dated after the last launch when it is unknown; time played and the Order choice are kept in their own files (damaged lines skipped, the play record untouched) and read as "1 h 12 min played in all, longest 40 min"; commit subjects lose their "Clock: " or "Clock README: " start (not another app's), and the detail pane shows the newest two with their days and how many more; README, check and refactor subjects are not news, and the quiet rule is the same as the site's (the check reads `news-kind.ts` and compares). The launch steps: javac or jar under the launch means building (even beside a short java, as NathaNOS's build has), the app's java means opening for 2 seconds and running after, nothing yet means getting ready, and the running clock reads "0:07", "3:12" and "1:02:03". Last, the Start menu: only the apps without real keys get a shortcut, each with its own name, running `run.ps1 old <App>` by its full path; the icon file holds one 256 px PNG; and removing deletes the shortcut, the icon and the empty folder (no shortcut is really made: that needs PowerShell). From the repo root:

```
javac -d out/check/Launcher Launcher/src/launcher/*.java Launcher/test/launcher/*.java
java -ea -cp out/check/Launcher launcher.LauncherCheck
```
